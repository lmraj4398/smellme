# File storage (Cloudflare R2)

All images and receipts live in Cloudflare R2. The API never handles the file bytes: it checks the request, hands the
browser a signed URL, and the browser uploads straight to R2.

## What goes where

| Folder (`R2_FOLDERS`) | Bucket | Used by | Rules |
|---|---|---|---|
| `media` | public (`R2_PUBLIC_BUCKET`) | product photos (admin → Products), site images (admin → Content) | JPEG, PNG, WebP, AVIF; up to 5 MB |
| `receipts` | private (`R2_PRIVATE_BUCKET`) | payment receipts (storefront → Order; staff view them in admin → Orders) | JPEG, PNG, WebP, PDF; up to 5 MB; key contains the order id |

## One place in the code

`src/common/r2/` is the only code that talks to R2. `R2Module` is global, so any service can inject `R2Service`:

```ts
constructor(private readonly r2: R2Service) {}

await this.r2.presignUpload('media', 'image/webp', size);          // -> { key, upload_url, public_url, headers }
await this.r2.presignUpload('receipts', 'application/pdf', size, orderId);
this.r2.isValidKey('receipts', key, orderId);                       // only keys we generated, for this order
await this.r2.head('receipts', key);                                // did the browser really upload it?
await this.r2.signedGetUrl('receipts', key, 300);                   // 5-minute link to a private file
this.r2.publicUrl(key);                                             // URL of a public file
await this.r2.delete('media', key);                                 // best-effort cleanup
await this.r2.put('media', buffer, 'image/png');                    // a file the server made itself
```

Keys are always generated by the server (`<prefix>/[<scope>/]<uuid>.<ext>`); the extension comes from the validated
content type, never from the client's file name.

### Adding another upload type (e.g. brand logos)

1. Add a rule to `R2_FOLDERS` in `src/common/r2/r2.folders.ts` (prefix, public or private, allowed types, size, scoped or not).
2. Call `presignUpload('<folder>', ...)` from your controller, and save only keys that pass `isValidKey`.
3. In the admin, reuse `uploadImage()` in `admin/src/api/uploads.api.ts` (it compresses, signs, uploads and returns the key).

## Setting it up

1. Create two buckets in the Cloudflare dashboard: a public one (attach a custom domain such as `cdn.smellme.in`) and a private one.
2. Create an R2 API token with Object Read & Write on both buckets.
3. Fill in `environments/.env.production` (see `environments/.env.example`): `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`,
   `R2_SECRET_ACCESS_KEY`, `R2_PUBLIC_BUCKET`, `R2_PRIVATE_BUCKET`, `R2_PUBLIC_URL`.
4. **Add a CORS rule to both buckets.** Browsers upload with `PUT` directly to R2, which fails without it.
   (R2 → bucket → Settings → CORS policy.)

   ```json
   [
     {
       "AllowedOrigins": ["https://smellme.in"],
       "AllowedMethods": ["PUT", "GET", "HEAD"],
       "AllowedHeaders": ["Content-Type", "Cache-Control"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

   For local development also allow `http://localhost:5183`, `http://localhost:5184` and `http://localhost:3011`.

If R2 is not configured the API still starts; uploading answers `503 Image storage is not configured` and nothing else breaks.
